AEC3 and continuous render path. It is not a real translation Provider session,
not a four-worker matrix run, and not release acceptance. vm131 is not renamed or
impersonated. The original workspace and its index remain untouched.

## Real native behavior

- Bind the real interactive vm171 identity and explicit physical render endpoint.
- Use unchanged canonical English and newly generated Chinese, without process
  exclusion, muting capture, deleting input blocks, or disabling translation audio.
- Arm English playback only after the active native capture handle acknowledges
  a successful `IAudioClient.Start`. Bind the acknowledgement to that handle, not
  optimistic `stream_bound`/init state or the endpoint name. Idle loopback may
  have zero frames at arm; final acceptance still requires complete advancing
  PCM/clock evidence. Replaced/exited owners and Start failures cannot arm.
- Native code owns the exact hash-bound English injector process; a JobObject owns
  the desktop and all descendants. No caller-created successful media markers.
- Feed 2400-frame/100 ms PCM increments into one production NativeDesktopStream.
  Preserve the production 800 ms startup buffer / 1000 ms maximum startup wait.
- Execute double-talk, 80 ms delay and 160 ms + soft-clip phases on actual render.
- The source ends only when actual IAudioClock crosses its full original PCM span
  and endpoint padding drains. Cue creation or wall-clock estimates are not enough.
- Continue Chinese speech and live capture after English completion. Drain render,
  then require two seconds of fresh advancing quiet capture. Polling/capture gaps
  and new activity reset the quiet interval. The 180-second input deadline only fails.
  The existing 195-second outer cap is unchanged; the owned JobObject has a
  190-second bound so native startup/sealing do not compete with the input budget,
  with the final five seconds reserved for forced cleanup. No timeout grants pass.

## Evidence and thresholds

Retain original source PCM, linear AEC reference, transformed physical render PCM,
pre/post-AEC capture, QPC/frame/session/owner/reset metadata, source clock records,
terminal seals and their hashes. The independent schema2 analyzer validates these
files and invokes the pinned, existing `omni-benchmark.exe audio aec-closed-loop`
algorithm without rebuilding it or promoting the old diagnostic-only analyzer.
The old schema1 tap checker cannot certify schema2 delay-prefix gaps; the new
analyzer independently proves those gaps and seals before reporting tap evidence.

Every stage must pass the unchanged 20 dB isolated translation attenuation,
English source gain within +/-3 dB and >=95% coverage targets. The voiced
source-ended tail is analyzed independently; it must have at least one second of
physical speech followed by the open-capture quiet interval. Missing clocks,
insufficient windows, hash errors, wrong references and frame holes are
indeterminate and fail closed. Operation completion is never quality acceptance.

The final result always declares `releaseEligible=false`,
`realTranslationLifecycleVerified=false`, `modelInputLeakageVerified=false` and
`semanticLeakageChainVerified=false`. No artificial Provider events or model-input
PCM are created. Original paid-c03 lifecycle/semantic gates remain unverified by
this local simulation. A local acoustic pass cannot update a matrix success index.

## Diagnostic source-clock failures

`aec-source-playback-clock-failures.jsonl`: raw position/frequency/QPC/padding,
computed origin, the last accepted anchor and the validation error. It flushes
and syncs accepted and rejected evidence before returning failure. Rejected
observations never change the anchor or count as successful coverage, and a
latched error prevents a later `finish()` from manufacturing success. The fixed
1 ms origin-consistency bound and all acoustic targets remain unchanged.

A standalone source-clock probe is diagnostic only: it cannot certify c03,
Provider lifecycle, real-time translation, AEC suppression or matrix acceptance.
Keep its receipt, original English asset identity, binary hash and rejected
observations separate from local acoustic simulation results.

The frozen vm171 five-point diagnostic still fails the first-anchor rule. Its

from replacing global validation. More complete diagnostic evidence is needed
before changing any alignment model or mapping rule.

## Full source-clock diagnostic channel

The injector flag `--diagnostic-source-clock-trace` is isolated from c03. It
requires a 48 kHz reference path and unchanged full media: cropping, gain, added
silence and reference-only playback are rejected. It keeps observing the same
native client after the first strict error, until endpoint padding drains and
IAudioClock position/frequency crosses the complete source frame span, within
the original absolute safety deadline. The strict error remains latched. The
diagnostic receipt always has `passed=false`, `diagnosticOnly=true`, and a
nonzero process exit; it cannot be a healthy c03 media completion.

The raw JSONL retains independent before/after QPC and its frequency. The current
wasapi wrapper does not expose successful HRESULT accuracy distinctions, so
`rawClockHresult=null` and `rawClockAccuracyAvailable=false` are honest unknowns.
No S_OK is invented. The independent offline diagnostic analyzer computes clock
facts only and never grants acoustic, Provider or release acceptance.

## Incremental render event scheduling (2026-10-02)

The native incremental speaker client uses `EventsShared` and binds its own
WASAPI event before Start. It retains the 20 ms device-buffer request, 480-frame
writes, 800 ms software startup buffer and 1000 ms maximum startup wait. The
ordinary whole-cue and endpoint-recovery renderers are unchanged. Running
provider command reads are nonblocking; running idle/backpressure/drain waits
use the device event with a bounded 2 ms timeout instead of unconditional sleep.
The simulator uses the same production wait and records it as `nativeRenderWait`,
not `requestedSleep`. Successful signal, timeout and not-started results have
separate typed totals; rejected/unwound waits remain failures in their spans.

A signal authorizes another padding query, never acoustic output or completion.
Cancellation is checked before and after the wait without holding the ownership
mutex. Clients are released before their registered event and playback permit.
The pinned upstream wasapi 0.24.0 helper collapsed all non-signaled Win32 results
to EventTimeout and leaked a newly created event if registration failed. A small
source-provenance-checked vendored patch now owns the event before registration,
and classifies the original WAIT_* status: only WAIT_TIMEOUT is idle; failure
and unexpected statuses propagate. No LastError-clearing workaround remains.
The event is registered last in endpoint construction. The library-only vendor
manifest preserves production dependencies, omitting only example/dev tooling;
upstream source and minimal patch identities are explicitly recorded. This core
boundary requires both consumer suites, provenance checks and human review.

Deterministic tests use the observed 1056-frame capacity: 960-frame padding
leaves only 96 free frames; each normal engine wake allows an unchanged
480-frame refill. A missed wake that empties padding to zero still fails,
retaining the queued source before cleanup. Timeouts and event signals cannot
manufacture a receipt, reopen a client, drop PCM or relax an AEC threshold.
The diagnostic timing analyzer is included in the existing local speech test
command and remains diagnostic-only, never a replacement quality analyzer.

This scheduling patch still requires frozen real-device evidence. Passing its
unit tests is not an AEC acoustic pass, a paid c03 pass or release acceptance.

The vendor attributes preserve upstream CRLF/spacing instead of formatting
hash-pinned files; its inventory/hash gate detects any content change. Newly
written event tests retain the ordinary whitespace checks. This preservation
exception changes no PCM, acoustic threshold or runtime failure acceptance.

## Result-bound native wake diagnostics (2026-10-02)

Pump timing schema v2 records `nativeRenderWake` on every span, including each
per-part maximum. Only a completed `nativeRenderWait` has a typed
`notStarted`, `signaled` or `timedOut` value. Rejected/unwound waits and every
other part have null. The returned native result, duration/QPC span, maximum
and aggregate wake totals are recorded together, after the operation returns;
no recorder borrow crosses a callback. Generic measurement cannot create a
completed native wait without this identity. Retention remains bounded to 512
spans and preserves an evicted maximum's original wake identity.

The offline timing analyzer rejects v1 (individual identity is unavailable),
checks retained/global wake counts, and compares all maximum/retained identity
fields at the same sequence. Its fault-adjacent classification is diagnostic
only: a signaled result does not timestamp engine signaling or prove dispatch
latency, and a timeout result alone does not prove timer quantization. Actual
raw WAIT_FAILED and unknown statuses remain errors through the pinned vendor;
only WAIT_TIMEOUT maps to `timedOut`. Historical receipts are not rewritten.

This change adds no scheduling priority, timer-resolution change, buffer,
timeout, PCM drop, clock tolerance or acoustic acceptance. The next frozen
full-material vm171 run is a discriminator, not a guaranteed acoustic pass.
