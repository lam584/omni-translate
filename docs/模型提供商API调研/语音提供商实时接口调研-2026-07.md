# 语音模型提供商实时接口调研（2026-07）

> 面向看片模式（watch mode）实时语音翻译链路的实现级调研。信息以各家官方文档为准，OpenAI 关键端点（realtime translation / transcription）已逐条与 developers.openai.com 官方文档核对。
> 现有基线：阿里云 DashScope Realtime WS（`wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=...`），协议为 OpenAI Realtime 兼容方言。

## 1. OpenAI（本次适配的主目标）

### 1.1 专用实时翻译端点（看片模式首选）

- 模型：`gpt-realtime-translate`（2026-07 发布，$0.034/分钟，按音频时长计费）
- 端点：`wss://api.openai.com/v1/realtime/translations?model=gpt-realtime-translate`
- 鉴权：`Authorization: Bearer <KEY>`（无需 OpenAI-Beta 头）
- 音频输入：base64 24kHz mono PCM16，客户端事件 `session.input_audio_buffer.append`（注意 `session.` 前缀命名空间）
- 配置：`session.update` → `session.audio.output.language`（ISO 639-1 目标语），无 VAD/turn detection，模型对连续音频流持续输出
- 服务端事件：
  - `session.input_transcript.delta` — 源语转写增量
  - `session.output_transcript.delta` — 译文增量
  - `session.output_audio.delta` — 翻译语音（纯字幕方案可忽略）
- 关闭：发 `session.close`，继续收事件直到 `session.closed`（排空尾部译文）再断开
- 特点：单连接同时产出双语字幕流，无轮次边界（cue 切分需客户端按空闲间隔自行处理）；70+ 输入语言 → 13 种输出语言；16K 上下文；不支持 function calling

### 1.2 通用 Realtime GA（对话式，instructions 驱动翻译）

- 模型：`gpt-realtime-2.1`（旗舰，$32/$64 per 1M audio tokens）、`gpt-realtime-2.1-mini`（$10/$20）、`gpt-realtime`（旧 GA 别名）
- 端点：`wss://api.openai.com/v1/realtime?model=...`
- GA 迁移雷点（相对 beta）：
  - 不要再带 `OpenAI-Beta: realtime=v1` 头
  - 配置嵌套改为 `session.audio.input/output`，`session.type: "realtime"`
  - 事件名 `response.output_audio.delta` / `response.output_audio_transcript.delta`（beta 为 `response.audio.delta` / `response.audio_transcript.delta`）
  - `response.create` 用 `output_modalities`（beta 为 `modalities`）
- 输入转写需显式开启：`session.audio.input.transcription: {"model": "gpt-4o-mini-transcribe"}`，事件 `conversation.item.input_audio_transcription.delta/.completed`
- VAD：`server_vad`（threshold/prefix_padding_ms/silence_duration_ms/create_response/interrupt_response）或 `semantic_vad`（eagerness）；`turn_detection: null` + 手动 `input_audio_buffer.commit` 为 push-to-talk
- 音频：24kHz mono PCM16 base64；噪声抑制 `audio.input.noise_reduction: {"type":"near_field"|"far_field"}`（看片模式建议关闭，避免滤掉歌声/远场人声）

### 1.3 实时纯转写会话（配合二次翻译模式）

- 端点：`wss://api.openai.com/v1/realtime?intent=transcription`（URL 不带 model）
- 配置：`session.update` → `session.type: "transcription"`，`session.audio.input.transcription.model` 指定转写模型
- 模型：
  - `gpt-realtime-whisper`（推荐，原生流式，$0.017/分钟；独有 `delay` 参数 minimal/low/medium/high/xhigh；官方建议 `turn_detection: null` + 手动 commit）
  - `gpt-4o-transcribe` / `gpt-4o-mini-transcribe` / `whisper-1`（按回合出转写，配 server_vad/semantic_vad）
- 事件：`conversation.item.input_audio_transcription.delta/.completed`；无 `response.*`
- 用法：转写会话只出源语字幕，译文交给"二次翻译"模式的文本 LLM（任意 openai-compatible provider）

### 1.4 HTTP 音频 API（非实时，备选）

- `POST /v1/audio/transcriptions`：gpt-4o-transcribe 系支持 SSE 流（`stream=true`，事件 transcript.text.delta/done）；`gpt-4o-transcribe-diarize` 支持说话人分离
- `POST /v1/audio/speech`（TTS）：`gpt-4o-mini-tts`（支持 instructions 控制语气），格式含 pcm（24kHz）/wav 低延迟流式
- Azure OpenAI 差异：`wss://{resource}.openai.azure.com/openai/v1/realtime?model={部署名}`，鉴权 `api-key` 头；事件协议与 OpenAI GA 一致

## 2. Google Gemini Live

- 模型：`gemini-3.1-flash-live-preview`（当前默认）、`gemini-2.5-flash-native-audio-preview-12-2025`
- 端点：`wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?key=KEY`（或 `x-goog-api-key` 头）；客户端场景推荐临时令牌（`POST /v1beta/auth_tokens`）
- 音频：输入 16kHz mono PCM16（`realtimeInput.audio` + mimeType `audio/pcm;rate=16000`），输出 24kHz PCM
- 字幕关键配置：setup 中 `inputAudioTranscription: {}` + `outputAudioTranscription: {}` → `serverContent.inputTranscription/outputTranscription.text` 流式返回
- **会话时长硬限制**：纯音频约 15 分钟被服务端切断；必须配 `sessionResumption: {}`（收 `sessionResumptionUpdate.newHandle`，重连时带 handle）+ `contextWindowCompression.slidingWindow` 才能长时间看片；断线前收到 `goAway.timeLeft` 预告
- VAD：`realtimeInputConfig.automaticActivityDetection`（灵敏度/静音时长可调）；手动模式用 `activityStart`/`activityEnd`
- 价格：3.1-flash-live 音频输入约 $0.005/分钟、输出约 $0.018/分钟

## 4. 阿里云 DashScope 新模型（现有链路可直接加模型名）

- `qwen3.5-livetranslate-flash-realtime`：60 语种（29 语音+文本），约 2.8s 延迟——现有 omni 链路已支持 livetranslate 方言
- `qwen3.5-omni-flash-realtime` / `qwen3.5-omni-plus-realtime`：semantic VAD、55 音色、单会话最长 120 分钟
- 结束会话需发 `session.finish` 等 `session.finished`（livetranslate 方言，防丢尾段）
- ASR-only：`qwen3-asr-flash-realtime`（stt.rs 现用）、`gummy-realtime-v1`（0.54 元/小时）

## 5. 其他西方提供商（ASR-only / TTS-only 候选）

- **Deepgram**：`wss://api.deepgram.com/v1/listen`（nova-3，$0.0077/分钟，200-300ms 延迟）；新 Flux（`/v2/listen`）内置轮次检测。无内置翻译。
- **ElevenLabs**：Scribe v2 Realtime STT（`wss://api.elevenlabs.io/v1/speech-to-text/realtime`，~150ms）；流式 TTS WS（`.../stream-input`）。
- **Groq**：OpenAI 兼容 `/openai/v1/audio/transcriptions`，whisper-large-v3-turbo $0.04/小时，无流式（伪实时需自切段）。

## 6. 本次适配落地对照

| 路由 | 模型判定 | Rust 实现 |
|---|---|---|
| OpenAI Translation 方言 | kind=openai-compatible 且模型含 `translate` | `audio/openai_realtime.rs`（/v1/realtime/translations） |
| OpenAI Conversation 方言 | 模型含 `realtime`/`live`（非 translate/transcribe） | 同上（GA 协议） |
| OpenAI Transcription 方言 | 模型含 `transcribe`/`whisper` | 同上（?intent=transcription，配二次翻译） |
| Gemini Live | realtimeAudioMode 为 `gemini_*` | `audio/gemini_live.rs`（16kHz 重采样 + sessionResumption） |
| 智谱 GLM FlatCompat 方言 | kind=openai-compatible 且模型含 `glm` | `audio/openai_realtime.rs`（beta 扁平 session + session.model 字段，16kHz，`response.text.delta`；实验性，以智谱文档为准） |
| 腾讯实时语音翻译 | base_url 含 asr.cloud.tencent.com / template-tencent-speech / 模型 hunyuan-translation* | `audio/tencent_speech_translate.rs`（HmacSha1 URL 签名、二进制帧、sentence_end 句级提交；凭据格式 `appid\|SecretId\|SecretKey`） |
| Azure OpenAI Realtime | template-azure-openai（api-key 头 + 部署名作 model） | 复用 `audio/openai_realtime.rs`（URL 构造对 `/openai/v1` 前缀天然兼容） |
| 阿里云 Omni/LiveTranslate | 模型含 realtime+omni/livetranslate | `audio/omni/*`（不变） |

采集侧恒为 48kHz 双声道 f32-le，各 worker 经 `audio/pcm_resample.rs` 转为提供商要求的采样率（OpenAI 24k / Gemini 16k / DashScope 16k）。
