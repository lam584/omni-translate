# Watch Mode 短 CJK 回声拦截与 AEC 迭代方案（归档）

> **状态：已废弃，不得作为当前实现依据。** 2026-08-10 起，字幕、译文和译音的最终决策链已移除 `recent-output-echo`、`short-cjk-output-echo`、`echo-chain-fragment`、`echo-dominated` 以及播放后固定时间窗整段抑制。文本相似度只允许用于诊断展示，不得删除非空转录或阻止翻译。当前反馈治理由三个独立后端承担：Windows 进程级排除、Virtual Driver、WebRTC AEC3；旧纯 Rust AEC 与 shadow 双引擎路径均已从生产代码删除。本文件保留为历史根因记录，当前验收以三路线方案和真实链路矩阵为准。

## 1. 背景

在以下 Watch Session 报告中，用户说出一句话后，应用播放的翻译音频被系统输出采集链路重新采集，形成了持续反馈：

- `watch-session-report-qwen-audio-3.0-realtime-plus-2026-08-07T16-01-47-156Z.json`
- 典型链路：`源音频 -> 模型响应 -> 本机播放 -> 系统输出采集 -> ASR -> response.create -> 再次播放`
- 典型泄漏片段包括 `谁。`、`嘿，谁？`、`不到。`、`啥？`、`神。`

现有文本回声门控已经拦截了部分与最近输出相似的片段，但对单字或极短 CJK 片段覆盖不足。与此同时，AEC 虽然已启用且存在参考音频，实际平均消除量只有约 `0.1–1.5 dB`，说明声学消除基本没有稳定生效。

本次迭代不能只修复“用户说一句、系统重复一句”的单轮场景。Watch Mode 的真实输入可能是连续讲话、连续节目音频或多句快速衔接，翻译播放还可能与后续源语音重叠。因此，方案需要同时处理：

1. 单轮结束后的回声尾巴；
2. 连续源语音与翻译播放重叠；
3. ASR 将连续语音切成多个短片段；
4. 多个输出片段排队播放产生的长回声窗口；
5. 用户真实短句与短 CJK 回声之间的误判风险；
6. 双讲或重叠期间不能通过简单静音破坏真实输入。

## 2. 目标与非目标

### 2.1 目标

- 每个真实源语义片段最多触发一次对应的模型响应，不允许本机输出再次触发模型响应。
- 连续讲话期间，即使 ASR 输出单字或短句，也不能因为“短 CJK”规则被机械拦截。
- 播放期间的自有音频优先由 AEC 在声学层消除，文本门控只作为最后一道保护。
- 保留源音频与翻译播放重叠时的真实内容，不能把所有播放期间音频直接丢弃。
- 在报告中能够区分 AEC 成功、文本回声拦截、连续源语音放行和可疑片段放行。
- 新门控和新 AEC 能够独立启用、观测和回滚。

### 2.2 非目标

- 本次不试图通过单一文本相似度算法解决所有声学回声问题。
- 本次不把“播放期间禁止 ASR”作为默认方案，因为它会破坏连续输入。
- 本次不在缺少真实音频证据时盲目放宽 AEC 相关性阈值。
- 本次不要求根据语义猜测所有短句是否真实，判断应尽量依赖时序和声学证据。

## 3. 原方案的主要缺点

### 3.1 过度围绕单轮输入建模

原方案主要验证“用户停止说话后，翻译音频是否再次触发响应”。这只能覆盖最简单的回声尾巴，不能覆盖：

- 用户或节目仍在连续讲话时，第一句翻译已经开始播放；
- ASR 把同一段连续语音切成多个 final/completed 片段；
- 下一句真实源语音恰好很短，例如“是”“好”“然后呢”；
- 输出播放队列持续数秒，多个源片段和多个输出片段交叉重叠。

如果仍然逐个 completed 文本独立判断，连续讲话中的真实短片段会被误判为回声。

### 3.2 过度依赖最近一条输出文本

真实播放可能包含多个排队片段。当前 ASR 片段可能对应正在播放的较早输出，而不是最近生成的输出。只比较一条 `recent output` 会同时造成漏拦截和误拦截。

### 3.3 短 CJK 规则存在天然歧义

把最小 CJK 长度从 2 改成 1 虽然能拦截 `谁。`、`啥？`、`神。`，也会误伤大量正常表达。短文本只能作为风险特征，不能单独决定丢弃。

### 3.4 文本门控无法替代 AEC

AEC 失败后，回声可能被 ASR 识别成完全不同的文字，例如 CJK 被识别成英文或近音词。此时文本相似度再强也无法可靠识别，所以必须修复声学层。

### 3.5 AEC 缺少定位根因所需的观测数据

当前汇总主要包含抑制次数和平均消除量，不能回答以下问题：

- 是否找到过有效对齐；
- 最佳延迟是否超出当前搜索范围；
- 是否发生持续时钟漂移；
- 声道、采样率或增益是否不匹配；
- 是相关性不足，还是残差判定阻止了抑制；
- 参考音频时间戳是否早于实际扬声器播放。

### 3.6 缺少连续流验收标准

仅断言“没有第二轮响应”还不够。系统也可能通过误删真实输入来达到该结果。必须同时统计真实源片段保留率、回声泄漏率、连续翻译完整率和延迟。

## 4. 总体设计

本次迭代采用三层防线：

1. **声学层 AEC**：从系统输出采集信号中减去本应用实际播放的音频；
2. **连续流判定层**：根据输入连续性、播放区间和声学指标判断片段属于真实源语音还是回声；
3. **文本安全门控层**：对仍然泄漏的高风险短 CJK 或近似输出文本进行最后拦截。

文本是否短、是否相似只占部分证据。最终判定至少要组合以下信息：

- ASR 片段对应的音频起止时间；
- 与一个或多个实际播放区间的重叠比例；
- 该片段是否属于播放开始前已经存在的连续输入；
- AEC 的相关性、估算延迟、消除量和残差；
- 与重叠播放片段及播放尾巴的文本相似度；
- 最近已经接受的源片段与当前片段之间的静音间隔；
- 当前是否处于输出队列持续播放状态。

## 5. 连续讲话处理模型

### 5.1 不再把 completed 文本当成孤立语句

新增输入连续性跟踪器，为每个 ASR completed 片段附加 `source_continuity_id`。连续性可以根据以下信号建立：

- 当前片段开始时间与上一片段结束时间之间的间隔；
- AEC 后音频中的持续语音活动；
- provider 提供的 item、turn 或 audio offset；
- 播放开始前是否已经存在源语音活动。

建议初始连续间隔阈值为 `800–1500 ms`，但该值必须通过真实报告校准，不作为不可调整的固定业务规则。

如果一段源语音在翻译播放前已经开始，并在播放期间持续存在，那么该连续性链上的后续短片段默认具有较强的“真实源语音”证据，不能仅因为它是单字 CJK 就拦截。

### 5.2 为每次实际播放建立区间和身份

每个播放片段记录：

- `playback_segment_id`；
- 文本及规范化文本；
- 参考 PCM 范围；
- 入队时间；
- 实际开始和结束时间；
- 设备、采样率和声道信息；
- 因端点缓冲估算出的可听区间；
- 回声尾巴截止时间。

回声门控比较的是与当前 ASR 音频区间重叠的播放片段集合，而不是简单比较“最近一条模型输出”。

### 5.3 连续流状态

建议维护以下状态，状态用于组织证据，不直接等价于丢弃策略：

| 状态 | 含义 | 默认处理 |
| --- | --- | --- |
| `source_active` | 存在连续源语音，尚未进入本机播放重叠 | 正常送入模型 |
| `source_with_playback` | 源语音延续到本机播放期间 | AEC 后优先保留源语音 |
| `playback_only_candidate` | 只有本机播放证据，没有前序源语音连续性 | 高风险回声判断 |
| `echo_tail` | 播放刚结束，仍可能存在设备尾音 | 使用短尾窗和 AEC 残差判断 |
| `uncertain_overlap` | 声学与文本证据冲突 | 保守放行或延迟到上下文确认，并记录诊断 |

### 5.4 连续讲话场景下的判定原则

#### 场景 A：源语音在播放前开始，并持续到播放期间

- 延续原 `source_continuity_id`；
- 不使用“播放期间一律抑制”；
- 短 CJK 只增加少量回声风险，不得单独触发拦截；
- 依靠 AEC 去除本机输出，保留剩余源语音；
- 如果 AEC 残差很高但源连续性明确，应放行并标记 `accepted-continuous-source-with-aec-risk`。

#### 场景 B：源语音已经停止，播放期间新出现短片段

- 若片段与正在播放或刚结束的输出高度相关，且 AEC 指标也指向纯回声，则拦截；
- 若只有单字 CJK 特征而缺少声学或文本重合证据，不直接拦截；
- 若持续出现多个短片段并形成输出驱动链，提高回声风险分数。

#### 场景 C：播放期间出现新的真实源语音

- 这是新的连续性链，不能因为它从播放期间开始就自动判定为回声；
- 使用 AEC 后残差信号的语音活动、与播放参考的低相关成分，以及后续片段连续性确认真实输入；
- 第一片段证据不足时，可以短暂延迟提交，而不是立即丢弃；
- 一旦后续片段证明形成稳定的新源语音链，应合并或放行此前暂存片段。

#### 场景 D：输出队列持续播放，同时源音频持续输入

- 回声参考必须按多个 `playback_segment_id` 连续维护；
- AEC 对齐状态不能在每个输出片段边界无条件重置；
- 文本门控应比较所有实际重叠的输出片段；
- 需要监控翻译积压，避免输出队列越来越长，使系统长期处于回声高风险状态。

### 5.5 可选的播放调度保护

如果连续源语音造成输出队列持续积压，可以引入独立的播放调度策略：

- 限制最大待播放时长；
- 合并过短翻译片段；
- 对过时的中间翻译不再播放；
- 必要时对本地扬声器播放做轻量 ducking，但不能停止 AEC 参考写入；
- 调度策略不得通过删除源 ASR 输入来解决积压。

播放调度属于第二阶段优化，不应和第一版 AEC 修复耦合上线。

## 6. 短 CJK 回声门控

### 6.1 风险评分而不是单条件判断

新增 `short-cjk-output-echo` 判断，但仅在多个高风险条件共同成立时拦截。建议风险特征包括：

- 来源文本只有 1–3 个 CJK 字符；
- 与实际播放区间高度重叠，或处于播放结束后的短尾窗；
- 与任一重叠播放文本存在字符重合、包含或高相似关系；
- AEC 检测到高参考相关性但残差仍泄漏；
- 没有播放前建立的源语音连续性；
- 当前片段与前一条已确认回声构成连续反馈链；
- ASR 片段很短且缺少后续真实语音延续。

强放行证据包括：

- 当前片段属于播放前已经开始的源连续性链；
- AEC 后存在明显的非参考语音成分；
- 后续片段组成稳定、连贯的新源语音；
- 与所有重叠播放文本均无有效关联；
- 片段发生在回声尾窗之外。

### 6.2 时间窗

- 实际播放期间：进入高风险判断，但不自动丢弃；
- 播放结束后的短尾窗：初始建议 `2–4 秒`；
- 文本完全一致：保留现有较长回声窗口；
- 所有阈值都使用具名配置或常量，并写入诊断报告。

### 6.3 原因码

至少区分以下结果：

- `recent-output-echo`
- `short-cjk-output-echo`
- `aec-pure-echo`
- `accepted-continuous-source`
- `accepted-new-source-during-playback`
- `accepted-uncertain-overlap`

报告中同时记录参与判断的播放区间、连续性 ID、重叠比例和主要声学指标，避免只留下一个不可解释的布尔结果。

## 7. AEC 诊断与修复

### 7.1 先补齐诊断

扩展 `EchoCancellationResult` 和周期汇总，至少记录：

- 是否找到有效对齐；
- 最佳相关系数；
- 估算延迟及其变化；
- 参考、采集和残差 RMS；
- 估算回声增益；
- 消除前后 dB；
- 尾部相关系数；
- 当前声道和采样率；
- 未执行抑制的具体原因。

日志输出聚合统计，例如 p50、p95 和最大值，避免逐音频块刷屏。

增加显式诊断模式，在用户主动开启时保存有界的参考 PCM、采集 PCM 和 AEC 输出，用于离线确定性重放。默认不导出原始音频。

### 7.2 根因分类

使用真实样本判断失效属于哪一类：

1. 实际端点延迟超出当前约 300 ms 搜索范围；
2. 参考写入时间与扬声器真实开始播放时间不一致；
3. WASAPI 采集格式、采样率或声道映射与假设不一致；
4. 播放和采集时钟持续漂移；
5. 系统增强、限幅、重采样或其他非线性处理破坏简单缩放模型；
6. 对齐窗口太短，连续语音和静音切换时相关性不稳定。

### 7.3 状态化对齐

如果真实样本确认是对齐问题，采用状态化方案：

- 新播放周期开始时在较宽范围内捕获延迟，例如 `0–1000 ms`；
- 捕获成功后锁定延迟，只在约 `±20 ms` 范围内跟踪漂移；
- 使用跨多个音频块的窗口计算相关性；
- 对不同声道分别验证映射和估算增益；
- 连续播放片段之间保留对齐状态；
- 设备切换、长静音或相关性持续下降时重置；
- 只有高相关且低残差的纯回声窗口才设置 `suppress_asr`；
- 存在明显非参考语音成分时保留音频。

具体搜索范围和阈值必须由真实重放数据确定，以上数值仅作为初始实验范围。

## 8. 实施阶段

### 阶段 0：基线和失败样本

- 将本次报告时间线转换为回归 fixture；
- 保存每个源片段、输出片段和 `response.create` 的相对时间；
- 增加连续讲话和多输出重叠的合成时间线；
- 明确当前回声泄漏率、真实源片段保留率和响应次数。

### 阶段 1：观测能力

- 扩展 AEC 结果和汇总指标；
- 建立播放区间和 `playback_segment_id`；
- 建立 `source_continuity_id`；
- 增加有界诊断音频导出和离线重放工具。

### 阶段 2：短 CJK 止血

- 使用播放重叠、连续性和文本证据联合拦截；
- 新增独立原因码；
- 不改变 AEC 算法；
- 先通过报告 fixture 和连续流正反例测试。

### 阶段 3：AEC 修复

- 使用真实 PCM 重放定位根因；
- 根据证据修复播放时钟、格式、声道或对齐算法；
- 新算法先以 shadow 模式输出判定，不影响 ASR；
- 确认双讲保留后切换为实际抑制。

### 阶段 4：播放调度与长时间稳定性

- 验证长时间连续输入和连续输出；
- 监控输出队列积压；
- 必要时增加过时输出丢弃、短片段合并或 ducking；
- 验证对齐状态跨多个播放片段不漂移。

## 9. 测试矩阵

### 9.1 回声正例

- 输出 `嘿。` 后识别到 `谁。`；
- 输出 `谁？` 后识别到 `嘿，谁？`；
- 输出 `嘿，谁？` 后识别到 `不到。`、`啥？`、`神。`；
- 多个输出片段排队时，回声对应较早播放片段；
- 播放结束后设备尾音继续被采集；
- 回声被 ASR 识别为不同语言或近音文本。

### 9.2 真实输入反例

- 播放结束较久后，用户正常回答一个 CJK 字符；
- 用户连续说话，ASR 将一句话切成多个短 CJK 片段；
- 源语音在播放前开始，并持续覆盖整个播放区间；
- 播放期间开始新的真实句子；
- 用户重复了系统刚刚说过的词，但声学证据显示是新的真实输入；
- 英文或其他语言连续输入与中文翻译播放重叠。

### 9.3 长时间场景

- 连续输入 1 分钟，翻译输出持续播放；
- 快速分句导致输出队列积压；
- 播放片段之间无静音；
- 中途切换输出设备；
- 中途暂停和恢复源音频；
- AEC 暂时失锁后重新捕获延迟。

## 10. 验收指标

不能只用“没有重复响应”作为成功标准，至少同时观察：

| 指标 | 初始目标 |
| --- | --- |
| 自有输出触发的额外 `response.create` | 0 |

建议拆分为独立提交和开关：

1. AEC 诊断、播放区间和输入连续性基础设施；
