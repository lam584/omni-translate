# Omni Translate 架构说明

## 1. 架构总览

系统采用六层结构：
1. Desktop Shell：Tauri 2 + React 桌面界面、字幕浮窗、托盘和设置页。
2. Core Runtime：Rust Core，负责会话编排、状态管理、诊断和配置读写。
3. Audio Layer：系统音频采集、麦克风采集、分段、混音和延迟补偿。
4. AI Gateway：ASR、Translation Provider、TTS 的统一编排层。
5. Bridge Service：虚拟麦克风用户态桥接服务。
6. Driver/Installer：Windows 虚拟麦克风驱动与安装、回滚、自检链路。

## 2. 关键原则

1. 目标不变，路径分层。
2. 驱动和安装器独立交付。
3. Provider 统一网关，前端不直接请求模型接口。
4. 实时音频面与控制面分离。
5. 配置采用单一真相源，避免双写。
6. Provider 采用模板优先与能力探测前置策略。
7. 字幕优先于译音，在高延迟时优先保证字幕不断流。

## 3. 技术栈

1. Desktop Shell：Tauri 2。
2. Frontend：React 19 + TypeScript + Vite。
3. UI：React 组件 + CSS。
4. Core：Rust + Serde。
5. Audio：windows-rs + WASAPI。
6. Persistence：SQLite。
7. Secrets：Windows Credential Manager。
8. Installer：PowerShell 安装与发布脚本。

## 4. 模块边界

### 4.1 Desktop App

负责：
1. 页面渲染。
2. 快速配置。
3. 字幕浮窗。
4. 诊断界面。

### 4.2 Rust Core

负责：
1. 会话状态。
2. 模式预设。
3. 配置读写。
4. 统一命令与事件协议。

### 4.3 Audio Layer

负责：
1. 系统音频与麦克风采集。
2. VAD 与分段。
3. 原音和译音混音。
4. 延迟补偿。

### 4.4 AI Gateway

负责：
1. Provider 模板。
2. Provider 能力探测。
3. ASR、翻译、TTS 编排。
4. 术语模板注入。
5. 字幕优先调度和译音回退策略。

### 4.5 Bridge Service

负责：
1. 将 TTS 音频帧送入虚拟麦克风。
2. 与驱动进行用户态通信。

### 4.6 Driver / Installer

负责：
1. 虚拟麦克风驱动安装。
2. 驱动状态检测与回滚。
3. 正式版和开发版安装链路分离。

## 5. 数据流

### 5.1 入站翻译链路

系统音频/进程音频 -> VAD -> ASR -> Translation Provider -> Subtitle Engine -> 中文 TTS -> Mixer -> 扬声器

### 5.2 出站翻译链路

麦克风 -> VAD -> 中文 ASR -> Translation Provider -> 目标语言 TTS -> Bridge Service -> 虚拟麦克风

### 5.3 入站与出站音频运行态

当前阶段已经把音频主链路明确拆成两条运行态：
1. 入站链路：系统输出采集 -> 预缓冲 -> 分段 -> 字幕/TTS。
2. 出站链路：麦克风采集 -> 预缓冲 -> 分段 -> 翻译 -> 虚拟麦克风或本地监听。
入站链路最小状态字段：
1. 输入设备标识。
2. capture state，例如 idle、armed、capturing、buffering、muted。
3. preBufferState，例如 cold、primed、ready。
4. 入站缓冲时长。
5. 输出目标列表，至少包括 subtitle-engine 和 speaker/monitor。
出站链路最小状态字段：
1. 麦克风设备标识。
2. 录制状态与静音状态。
3. 出站缓冲时长。
4. 虚拟麦克风和本地监听的输出目标列表。
5. Push-to-talk 状态。

### 5.4 调度策略

1. 字幕和译音必须是两个独立调度结果。
2. 当 Provider 延迟升高时，Subtitle Engine 先产出文本结果，TTS 可等待或降级。
3. Diagnostics 需要能观察采集、识别、翻译、播报和输出各阶段耗时。
4. 当前主链路至少需要能表达“字幕已出、译音待补”这一中间状态，禁止把它压扁成单一完成态。
补充触发规则：
1. 当实测延迟高于预算阈值时，触发 `latency-high`，字幕继续输出，译音切换到 deferred 或 queued。
2. 当 Provider 探测结果为“不推荐实时”时，触发 `probe-risk`，默认关闭译音叠加，仅保留字幕优先链路。
3. 当探测结果可用且延迟回到预算内时，恢复 `normal`，允许字幕与译音并行，但字幕仍先提交。

### 5.5 TTS 播报占位链路

当前阶段先冻结从译文到播报控制的最小链路，字段包括：
1. 是否开启播报。
2. 播报目标语言。
3. 音色或 voice preset 标识。
4. 输出目的地，当前允许本地扬声器、虚拟麦克风或双输出。
5. 是否等待字幕先完成。
6. 当前播报状态，至少覆盖 idle、waiting-subtitle、queued、playing。
占位事件流：
1. `tts.requested`：字幕片段完成后生成播报请求。
2. `tts.deferred`：当前会话命中字母优先规则，播报暂缓。
3. `tts.playback.started`：允许进入本地播放或虚拟麦克风输出。
4. `tts.playback.completed`：当前播报片段结束。

### 5.6 术语模板注入规则

当前术语注入机制采用场景模板驱动，至少覆盖：
1. 视频同传。
2. 游戏语音。
3. 语音房。
注入优先级规则：
1. 场景模板负责给出该场景默认 promptTemplateId、绑定包和顺序基线。
2. `scenario-first` 模式下先注入场景模板，再合并用户术语包，再追加社区术语包。
3. `user-first` 模式下先应用用户术语包，再合并游戏词典或场景词典，最后补充社区术语包。
4. 社区术语包只能补充默认词条，不能覆盖用户显式条目。

## 6. Provider 策略

### 6.1 模板化接入

首版只把两类 Provider 作为官方模板：
1. OpenAI 兼容接口。
2. DashScope。
模板负责定义：
1. 必填字段。
2. 推荐字段。
3. 高级字段。
4. 请求模式，例如 HTTP 或 WebSocket。
5. 模板版本与来源标识。
6. UI 分组策略和模板字段到 Contract 字段的映射关系。
当前模板系统约束：
1. 官方模板当前只维护 OpenAI Compatible 和 DashScope 两类。
2. 模板可以给默认值，但不能重命名 Provider Contract 的基础字段。
3. 高级模式只能覆盖补充字段，不能重新定义 Contract 枚举或错误结构。

### 6.2 能力探测

Provider 接入前需要进行最小能力探测，至少包括：
1. 是否支持流式输出。
2. 是否满足实时使用所需的延迟门槛。
3. 是否返回稳定可解析的错误结构。
4. 是否适合作为实时翻译 Provider。
探测结果需要至少支持三类结论：
1. 可用。
2. 不推荐实时。
3. 不可用。
当前探测模型补充要求：
1. 探测结果需要缓存最近一次 verdict、检查时间和关键布尔结论，供 Provider 页面和 Diagnostics 共用。
2. 探测维度至少拆成流式能力、实时适用性、错误结构稳定性、响应格式稳定性四项检查。
3. 前端提示不能只显示“通过/失败”，还要给出字幕优先、禁用译音、推荐请求模式等可操作指引。

### 6.3 术语模板注入

术语模板属于 AI Gateway 的一部分，而不是页面层的临时字符串拼接。首版约束如下：
1. 术语模板按场景组织，并绑定默认 promptTemplateId。
2. 注入顺序必须显式可配置，至少支持 `scenario-first` 和 `user-first` 两种策略。
3. 用户术语包、社区术语包和游戏词典都必须作为独立来源进入合并规则。
4. 术语模板只定义输入顺序和来源优先级，不承担在线市场或复杂冲突 UI。

### 6.4 社区术语包格式规范

当前社区术语包与用户导出包共用同一套 manifest 结构。
最小字段：
1. manifestVersion、packageId、version。
2. kind、scenario、source。
3. conflictPolicy、localePair、compatibility。
4. entries，其中每个词条至少包含 id、sourceTerm、targetTerm。
当前格式约束：
1. 导出器必须输出完整 manifest，不允许只输出词条数组。
2. 社区包必须保留 author、source 和 version，便于溯源和兼容判断。
3. `keep-user-entry` 模式下，社区包只能补充用户缺失词条，不能覆盖用户显式条目。
4. 当前格式只覆盖离线导入导出和社区分享，不包含云同步与市场评分字段。

## 7. 数据与配置存储

1. SQLite：Provider 元数据、预设、设备记录、术语索引、会话摘要。
2. Credential Manager：API Key、代理认证和未来 token。
3. TOML/JSON：导出快照、默认模板、实验开关。
4. 文件目录：日志、缓存、术语包、临时音频。
补充存储原则：
1. SQLite 是结构化配置与业务数据的主真相源。
2. Credential Manager 只保存敏感信息，不保存业务元数据。
3. TOML/JSON 只承担导出快照、默认模板和实验性配置，不承担当前生效配置真相源。
4. 日志、缓存、术语包和临时音频必须分目录存放，避免和主配置混用。
推荐目录策略：
1. AppData/Roaming：数据库、主配置、术语包。
2. AppData/Local：缓存、日志、临时音频、临时下载产物。

## 8. 安装、回滚与支持边界

1. 安装器负责主程序、运行时和驱动安装。
2. 驱动安装需要提权，且必须支持失败回滚。
3. 开发版与正式版安装链路必须分离处理。
4. 驱动异常不能阻塞字幕和本地播放等降级功能。
5. 产品侧必须区分稳定支持场景与实验性支持场景。
当前支持边界：
1. 默认稳定支持：看片系统音频采集、常规语音房/会议软件。
2. 默认实验性支持：复杂游戏语音场景、需要同时处理系统音频采集和虚拟麦克风输出的环境。
3. 实验性支持必须在 UI 和 Diagnostics 中给出判定依据，不能只给一个标签而没有说明。
补充安装链路约束：
1. 当前驱动模块按目录隔离到 `drivers/windows-virtual-mic`，Bridge Service 只保留 Rust native workspace：`apps/bridge-service-native`。
2. UAC 提权只在用户首次启用虚拟麦克风或显式点击修复动作时触发，不在普通字幕和本地播放流程中触发。
3. 安装顺序固定为：主程序发起安装计划 -> 安装器提权 -> 驱动注册 -> Bridge Service 启动 -> 握手校验。
4. 任何一步失败都必须中断后续步骤，并进入回滚计划。
回滚顺序：
1. 先停止 Bridge Service，避免仍有音频帧写入。
2. 再卸载驱动和设备注册信息。
3. 最后恢复主程序状态为“字幕可用、译音关闭”的降级态。
开发版与正式版边界：
1. 开发版允许测试签名驱动，但必须显式标记为 development 通道。
2. 正式版必须使用正式签名驱动，并执行更严格的版本校验。
3. 自动化步骤只覆盖安装、握手、版本比对和回滚，正式签名审核仍属于人工受控步骤。

## 9. 诊断与可观测性

系统至少需要提供以下诊断面：
1. 安装状态。
2. 驱动状态。
3. Provider 测试结果。
4. 设备状态。
5. 各阶段链路耗时。
6. 日志与问题导出入口。
当前驱动诊断最小字段：
1. driverHealth：至少区分 `not-installed`、`damaged`、`version-mismatch`、`running`。
2. bridgeState：至少区分 `stopped`、`starting`、`running`、`degraded`。
3. installPhase：至少区分 `planned`、`installing-driver`、`starting-bridge`、`verifying`、`rollback-required`、`ready`。
4. lastErrorCode：保留最近一次安装、握手或写入失败错误码。
5. recommendedAction：为 Diagnostics 页面和修复入口提供统一动作标识。
当前音频诊断最小字段：
1. inbound capture state 与 preBufferState。
2. outbound capture state、静音状态和 Push-to-talk 状态。
3. mixControl 中的原音保留、译音增益、duking 与监听模式。
4. 当前支持等级和支持矩阵命中的场景依据。
发布前最小校验面：
1. desktop verify。
2. native bridge check。
3. 版本一致性和文档存在性检查。
4. release manifest 生成。

## 10. 接口契约

当前需要冻结四类契约：
1. Audio Contract
2. Provider Contract
3. Driver Bridge Contract
4. OBS Integration Contract

### 10.1 Provider Contract

Provider Contract 当前已经先冻结为统一字段模型，用来覆盖 OpenAI 兼容接口和 DashScope 两类 Provider。
基础元数据字段：
1. providerId：Provider 唯一标识。
2. kind：Provider 类型，当前只允许 `openai-compatible` 和 `dashscope`。
3. displayName：展示名称。
4. baseUrl：统一入口地址。
5. transport：请求模式，当前允许 `http`、`streaming-http`、`websocket`。
6. region：区域字段，按模板可选。
7. model：当前激活模型。
8. capabilities：能力声明，当前用于表达 translation、realtime-translation、text-to-speech。
认证字段引用方式：
1. auth.kind：引用来源，当前允许 `credential-ref` 和 `env-ref`。
2. auth.reference：认证引用值，例如 Credential Manager 或环境变量路径。
3. auth.headerName：认证头字段名。
4. auth.scheme：认证方案，当前允许 `bearer`、`api-key`、`none`。
请求参数结构：
1. requestId、sessionId：链路关联标识。
2. model、transport：与元数据层保持同名。
3. sourceLanguage、targetLanguage：翻译方向。
4. stream：是否启用流式返回。
5. responseModalities：当前允许 `text` 和 `audio` 两类结果。
6. glossaryPackageIds：术语包挂载列表。
7. promptTemplateId：模板层注入的提示词模板标识。
8. timeoutMs、maxOutputTokens、temperature：请求控制字段。
9. messages：统一消息结构，支持 text 和 audio-reference 两类输入片段。
流式响应结构：
1. `session.started`：会话开始。
2. `translation.delta`：增量翻译文本。
3. `translation.completed`：分段翻译完成。
4. `audio.delta`：音频分片占位，用于后续 TTS 播报链路。
5. `usage.updated`：令牌或音频时长统计。
6. `response.completed`：整次响应结束。
错误返回结构：
1. code：统一错误码，当前至少覆盖认证失败、请求非法、限流、模型不支持、传输不可用、响应不可解析、超时、上游内部错误。
2. message：面向诊断和 UI 的统一错误消息。
3. retriable：是否允许重试。
4. httpStatus：可选 HTTP 状态码。
5. providerCode：上游原始错误码。
6. suggestion：给模板系统和诊断页的建议动作。
字段归属边界：
1. Contract 固定字段：providerId、baseUrl、model、transport、auth.reference 等基础输入字段。
2. Template 负责字段：promptTemplateId、region 和默认推荐值，不允许重命名 Contract 主字段。
3. Probe 负责字段：streamSupport、errorShapeStable、实时适用性等探测结果，不回写 Contract 输入字段定义。

### 10.2 Audio Contract

Audio Contract 当前已经冻结为系统音频、麦克风、混音、延迟补偿和 Push-to-talk 共用的统一字段模型。
输入源字段：
1. kind：当前允许 `system-output` 和 `microphone`。
2. sourceId、deviceId：输入源和设备标识。
3. state：当前允许 `idle`、`armed`、`capturing`、`buffering`、`muted`。
4. muted：静音状态。
5. bufferAheadMs：当前缓冲时长。
6. preBufferState：当前允许 `cold`、`primed`、`ready`。
输出目标字段：
1. kind：当前允许 `speaker`、`virtual-mic`、`subtitle-engine`、`monitor`。
2. targetId、deviceId：输出目标和设备标识。
3. enabled：当前目标是否启用。
帧与分段字段：
1. frameId、routeDirection、timestampMs。
2. encoding：当前固定为 `pcm16le`。
3. channelLayout、channelCount。
4. sampleRateHz：当前允许 16000、24000、48000。
5. frameCount 与 payloadRef。
6. segmentId、startedAtMs、endedAtMs、sourceFrameIds。
混音控制字段：
1. keepOriginalAudio：是否保留原音。
2. translatedAudioEnabled：是否开启译音。
3. translatedAudioGainDb、originalAudioGainDb：原音与译音增益。
4. duckingEnabled 与 duckingDepthPercent。
5. monitorMode：当前允许 `translated-only` 和 `original-and-translated`。
延迟补偿字段：
1. captureBufferMs。
2. translationBufferMs。
3. playbackBufferMs。
4. compensationMs。
Push-to-talk 字段：
1. enabled：是否启用。
2. hotkey：快捷键字段。
3. state：当前允许 `idle`、`armed`、`recording`。
4. releaseDelayMs：释放按键后的延时。

### 10.3 Driver Bridge Contract

Driver Bridge Contract 当前已经冻结为主程序、Bridge Service 和驱动之间的最小消息协议。
初始化字段：
1. requestId、sessionId：链路关联标识。
2. protocolVersion：当前固定为 `2026-05-10`。
3. installChannel：当前允许 `development` 和 `release`。
4. targetDeviceId：目标虚拟麦克风设备标识。
5. expectedDriverVersion、expectedBridgeVersion：主程序期望的版本对。
音频帧写入字段：
1. frameId、streamId：帧和流标识。
2. encoding：当前固定为 `pcm16le`。
3. channelLayout、channelCount：当前允许 mono/stereo 与 1/2 通道。
4. sampleRateHz：当前允许 16000、24000、48000。
5. frameCount、timestampMs：帧大小与时间戳。
6. payloadRef：主程序或 Bridge Service 访问音频负载的引用。
状态查询字段：
1. bridgeState：Bridge Service 运行态。
2. lifecycleState：当前生命周期阶段，例如 ready、writing、draining、error。
3. driverHealth：驱动健康结论。
4. driverVersion、bridgeVersion：当前版本信息。
5. queuedFrames、lastFrameTimestampMs：桥接层写入队列状态。
6. lastErrorCode：最近一次写入或安装异常。
错误事件结构：
1. code：当前至少覆盖 `driver.not-installed`、`driver.version-mismatch`、`driver.write-failed`、`bridge.not-ready`、`bridge.queue-overflow`、`bridge.permission-denied`、`bridge.timeout`、`installer.rollback-triggered`。
2. message：面向 Diagnostics 和日志的统一错误消息。
3. retriable：是否允许直接重试。
4. bridgeState、driverHealth：错误发生时的桥接与驱动状态。
5. suggestedAction：当前统一动作标识，至少覆盖重新安装驱动、重启 Bridge Service、回滚驱动、打开诊断详情。
关闭流程字段：
1. 主程序发送 `bridge.shutdown` 时必须带上 requestId、sessionId 和关闭原因。
2. 当前关闭原因至少包括 `session-ended`、`installer-rollback`、`manual-stop`。
3. 安装回滚触发时，Bridge Service 关闭优先级高于驱动卸载。

### 10.4 OBS Integration Contract

OBS Integration Contract 当前只冻结未来扩展所需的最小连接与输出边界，不在本阶段实现真实 OBS 控制器。
连接字段：
1. connectionId：连接唯一标识。
2. protocolVersion：当前固定为 `2026-05-10`。
3. transport：当前允许 `websocket` 和 `named-pipe`。
4. endpoint：OBS 地址或本地命名管道名。
5. auth：认证引用，当前允许 `credential-ref`、`env-ref`、`none`。
输出字段：
1. captionCommitMode：当前允许 `final-only` 和 `partial-and-final`。
2. outputs：输出绑定列表，至少覆盖 `subtitle-overlay`、`translation-status`、`scene-trigger`。
3. 输出绑定至少包含 sceneName、sourceName、enabled，可选 textField。
4. emitTranslationStatus：是否输出翻译状态文本。
失败策略字段：
1. degradeToDesktopOverlay：OBS 失败时是否回退桌面字幕浮窗。
2. retryOnDisconnect：是否自动重连。
3. retryBackoffMs：自动重连退避时间。
当前边界约束：
1. OBS 连接失败不得阻断主翻译链路。
2. `scene-trigger` 只保留未来切场扩展边界，不承诺本阶段自动切场。
3. Desktop Overlay 仍然是默认兜底展示面。

## 11. 协作与发布基线

当前仓库已经补齐最小协作与发布入口：
1. 根目录 `CONTRIBUTING.md` 负责区分 UI、Provider、Core、Driver、文档与测试入口。
2. 根脚本新增 `release:verify`、`release:manifest`、`release:prepare`。
3. `release:verify` 负责检查版本一致性、脚本完整性、文档存在性，并串联 desktop verify、contract gate 与 native bridge check。
4. `release:manifest` 负责生成 release-manifest.json，作为版本和交付内容快照。
