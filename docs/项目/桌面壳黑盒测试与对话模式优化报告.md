# 桌面壳黑盒测试与对话模式优化报告

## 测试范围

- 测试入口：Tauri 桌面壳 `omni-desktop-shell.exe`，未使用网页版。
- 核心路径：实时会话、对话模式、音频路由、停止与重启、诊断和自动恢复。
- 测试立场：首次使用产品的真实用户；重点检查可理解性、业务互斥、错误恢复和无效配置。
- 字幕悬浮窗：按产品要求不纳入本轮问题范围。

## 对话模式优化后的业务规则

1. 对话模式等同于 `voice-room`：系统音频采集对方声音，麦克风采集自己的声音，形成双向翻译；模型能力要求为 speech-to-speech。
2. 对话模式默认采用 AEC，虚拟驱动和 Bridge 是可选依赖，不影响对话可用性结论。
3. 同一时间只允许一个实时场景启动；切换场景必须先完成停止。
4. stopping 阶段禁止任何新启动，避免旧任务回写新会话状态。
5. 启动前必须存在兼容模型和当前可用的物理设备，否则在页面内立即给出修复指引。
6. 诊断结论必须区分“当前场景硬依赖”和“已安装但当前不用的可选组件”。

## 回归证据

- 桌面壳黑盒：确认对话模式同时启动系统音频和麦克风音频，运行时两个模式入口均锁定。
- 桌面壳黑盒：失效麦克风被阻止启动，并显示“当前麦克风不可用”提示。
- 桌面壳黑盒：失效设备下拉框显示“未连接”，不再空白。
- 桌面壳黑盒：对话/AEC 场景下，可选 Bridge 损坏不再产生关键问题。
- 前端验证：ESLint、TypeScript、527 项 Vitest、Vite 生产构建全部通过。
- 桌面后端验证：Cargo check 通过，265 项 Rust 测试全部通过。

## 后续建议

- 将场景能力约束下沉为共享契约，由配置页、启动页和 Rust 路由共同消费，避免三处规则漂移。
- 给设备热插拔增加事件驱动刷新；当前已经安全阻止无效启动，但仍需要用户手动重选设备。
- 增加真实双人声源的声学回归矩阵，覆盖耳机、外放、蓝牙免提和 USB 麦克风。
- 为 stopping、断网重连、模型限流和设备拔插建立桌面壳自动化回归用例。
